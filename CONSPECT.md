## 1. Зачем PostgreSQL

SQLite — «база в файле». PostgreSQL — **отдельный сервер**, к которому программы
подключаются по сети (даже если сервер на той же машине — это `localhost:5432`).

Выбирать PostgreSQL, когда (по уроку):

- данных гигабайты и больше — один файл уже неудобен;
- одновременно работают десятки и сотни пользователей;
- нужны надёжные транзакции, права доступа, резервное копирование;
- проект растёт и может выйти в продакшн.

Ориентир из урока: «если работа ведётся с более чем десятью пользователями — PostgreSQL».

## 2. SQLite vs PostgreSQL

| | SQLite | PostgreSQL |
|---|---|---|
| Форма | файл в проекте | сервер + клиент |
| Запуск | ничего не нужно | служба (`postgresql-x64-18`) и порт 5432 |
| Пользователи | файловая система | роли, пароли, права на объекты |
| Типы | гибкие | строгие: `INT`, `TEXT`, `NUMERIC(10,2)`, массивы |
| Плейсхолдер | `?` | `%s` |
| Нагрузка | одна запись | параллельные подключения |

Практический вывод: **способ подключения одинаковый** — меняются только пять переменных
в `.env`. Поэтому локальная и удалённая база (например, на Aiven.io) — это одна и та же схема
работы, разница лишь в значениях `DB_HOST`/`DB_PORT` и скорости ответа.

## 3. Установка (Windows)

- Скачать установщик с postgresql.org → Download → Windows → «Download the installer».
- Компоненты оставить все четыре, путь — по умолчанию.
- **Пароль суперпользователя `postgres`** — придумать и запомнить: он потребуется
  и в pgAdmin, и в `.env`, и нигде в проекте не хранится.
- Порт оставить **5432**.
- Stack Builder после установки не нужен — галочку снять.

Сервер запускается как фоновая служба и «приложением» не является. Проверка:

```powershell
Get-Service -Name '*postgres*'
Test-NetConnection localhost -Port 5432
```

## 4. pgAdmin: что там происходит

pgAdmin — графическая оболочка **к серверу**, а не сама база.

Путь объекта: **сервер → база данных → схема → таблица → строки**.

- `postgres` — служебная база, её не трогаем.
- `test` — наша база из задания.
- `public` — схема по умолчанию, в ней и работаем.
- Таблица `users`: `id` (integer, NOT NULL, первичный ключ), `name` (text), `age`
  (в уроке выбирают real, в задании — `INT` с проверкой `CHECK (age >= 0)`).

### Роли и права — откуда берётся `permission denied`

Урок отдельно советует не работать суперпользователем, а создать роль (например, `user`):

1. Роль входа/группы → Создать → задать имя → во вкладке «Права» включить вход и создание баз.
2. В конкретной базе — «Мастер назначения прав», выдать роли права на таблицы.
3. Задать роли пароль (Свойства → Определение → Пароль).
4. Если при создании таблиц всё равно `permission denied for schema public` — выдать роли
   права на схему `public` (Свойства схемы → Безопасность → добавить субъекта → все галочки).

**Вывод:** «нет доступа» — это не ошибка кода, а отсутствие прав на объект.

## 5. Подключение из Python

```text
python -m venv venv     # python -m = запусти модуль, venv = создай окружение, venv = имя папки
```

`requirements.txt`:

```text
psycopg2-binary
python-dotenv
```

`psycopg2-binary` — драйвер с готовым бинарником, компилятор C на машине не нужен.

`.env` (рядом с кодом, в git не попадает):

```text
DB_HOST=localhost
DB_PORT=5432
DB_NAME=test
DB_USER=postgres
DB_PASSWORD=...
```

Код подключения:

```python
import os
import psycopg2
from dotenv import load_dotenv

load_dotenv()          # .env → переменные окружения
conn = psycopg2.connect(
    host=os.getenv("DB_HOST"), port=os.getenv("DB_PORT"),
    dbname=os.getenv("DB_NAME"), user=os.getenv("DB_USER"),
    password=os.getenv("DB_PASSWORD"),
)
```

Важный момент урока: **не читать `.env` руками** (`open().split("=")`), а брать
`python-dotenv` — он корректно разбирает кавычки, комментарии и пробелы.

## 6. Драйвер и CRUD

Соединение и курсор:

```python
with conn, conn.cursor() as cur:      # транзакция + автозакрытие курсора
    cur.execute("SELECT id, name, age FROM users;")
    for row in cur.fetchall():        # fetchone() — одна строка, fetchall() — все
        print(row)
```

- `conn` — соединение с сервером;
- `cursor` — «рука», через которую выполняются запросы: `execute`, `fetchone`, `fetchall`;
- `with conn:` — commit при успехе, rollback при исключении;
- `%s` — плейсхолдер **всегда** `%s`, даже для чисел; значения передаются вторым аргументом.

Драйвер (опциональный пункт задания) — это класс, который прячет всю эту механику:
`create_tables`, `add_user`, `add_order`, `get_user_totals`. Его можно скопировать
в любой другой проект и пользоваться как библиотекой.

## 7. Задание

**Базовый трек:** таблица `users` + 3 записи, `main.py` с `SELECT * FROM users`, вывод
в консоль, закрытие соединения.

**Средний трек** (включает базовый): таблица `orders` со ссылкой на `users`
(`ON DELETE CASCADE`), вставки через код параметризованными запросами, агрегат
`LEFT JOIN + COALESCE(SUM(...))`, сортировка по сумме по убыванию, обработка ошибок.

**Критерии зачёта:**

- таблицы созданы, связь работает (проверяется удалением пользователя с заказами);
- ≥3 пользователя и ≥2 заказа у разных пользователей;
- JOIN + SUM + GROUP BY печатает корректные суммы, порядок сортировки соблюдён;
- исключения обработаны, соединение закрывается;
- в сдаче: `main.py`, `requirements.txt`, `.env.example` (без секретов), `README.md`.

## 8. Разбор нашего результата

Что лежит в `project/` и зачем:

| Файл | Роль |
|---|---|
| `main.py` | сценарий: подключиться → создать таблицы → наполнить → показать отчёт → проверить каскад |
| `postgres_driver.py` | драйвер: соединение, DDL, CRUD, агрегат; его же импортирует `main.py` |
| `ensure_database.py` | создать базу `test`, если её нет — замена ручному шагу в pgAdmin |
| `README.md` | запуск, переменные, критерии |
| `.env.example` | шаблон без секретов |

### Поток выполнения `main.py`

```text
PostgresDriver.from_env()        # собрать параметры из .env, проверить, что все заданы
with driver:                     # __enter__ → connect(); на выходе __exit__ → close()
    driver.create_tables()       # CREATE TABLE IF NOT EXISTS users/orders
    seed_if_empty(driver)        # вставки, только если таблицы пусты
    print_users(driver)          # базовый трек: SELECT из users
    print_totals(driver)         # средний трек: LEFT JOIN + SUM
    demonstrate_cascade(driver)  # удаление пользователя с заказом внутри транзакции + откат
# исключения psycopg2.Error / UnicodeDecodeError ловятся снаружи
```

Три решения, которых не было в подсказке урока:

1. **Идемпотентность.** Наполнение под условием `count_rows(...) == 0`. Второй запуск
   печатает «вставку пропускаю» и не задваивает данные — иначе каждый прогон добавлял бы
   ещё трёх пользователей.
2. **Проверка каскада без потери данных.** Временный пользователь с заказом создаётся
   внутри `with conn:`, удаляется, печатается «заказов стало 0», затем транзакция
   откатывается служебным исключением. Критерий зачёта проверен, реальные строки целы.
3. **Понятные ошибки.** Вместо голого трейсбека — сообщение и подсказка: неверный пароль,
   нет базы, сервер не отвечает.

### Ключевые места `postgres_driver.py`

```python
@classmethod
def from_env(cls) -> "PostgresDriver":
    load_dotenv()
    missing = [v for v in (...) if not os.getenv(v)]
    if missing:
        raise RuntimeError("Не заданы переменные окружения: ...")
```

Проверка до подключения: если `.env` забыли скопировать, человек увидит, **какие**
переменные не заданы, а не `KeyError`.

```python
def add_user(self, name: str, age: int) -> int:
    with conn, conn.cursor() as cur:
        cur.execute("INSERT INTO users (name, age) VALUES (%s, %s) RETURNING id;", (name, age))
        return cur.fetchone()[0]
```

`RETURNING id` — PostgreSQL сразу отдаёт сгенерированный `SERIAL`-ключ, без второго запроса.

```python
TOTALS_SQL = """
SELECT u.id, u.name, COALESCE(SUM(o.amount), 0) AS total_amount
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id, u.name
ORDER BY total_amount DESC, u.name ASC;
"""
```

`LEFT JOIN` держит в отчёте пользователей без заказов, `COALESCE` превращает `NULL` в 0,
сортировка — по убыванию, как в критерии.

### Что увидел бы пользователь

```text
=== Суммы заказов по пользователям (LEFT JOIN + SUM) ===
  Алиса —   1570.50      (1250.00 + 320.50)
  Борис —    780.00
  Вера  —      0.00      (заказов нет, но в отчёте есть)
```

## 9. Грабли, на которые мы наступили

| Грабли | Причина | Решение |
|---|---|---|
| `UnicodeDecodeError` вместо «неверный пароль» | `lc_messages = 'Russian_Russia.1251'`, psycopg2 ждёт UTF-8 | функция `readable_server_error()`: достаёт байты из `exc.object` и декодирует в cp1251 |
| Таблица `users` уже есть, но с другой структурой | в уроке её создали руками в pgAdmin, а потом пытались создать из кода | `DROP TABLE orders; DROP TABLE users;` и запустить заново |
| `no results to fetch` | `fetchone()` там, где строк нет | проверять результат или использовать `fetchall()` |
| `permission denied for schema public` | роль без прав на схему | выдать права на схему `public` |

Последние три — ровно то, на чём урок застрял на страницах 70–77; полезно помнить, что
это не «ошибка ИИ», а реальные состояния базы.

## 10. Самопроверка

1. **Чем `with conn:` отличается от `conn.commit()`?** — `with` откатывает транзакцию
   при исключении; `commit()` нужно не забыть вызвать.
2. **Почему `%s`, а не f-строка?** — драйвер экранирует значение; f-строка открывает
   SQL-инъекцию.
3. **Почему `LEFT JOIN`, а не `INNER JOIN`?** — нужны пользователи без заказов.
4. **Зачем `COALESCE(SUM(...), 0)`?** — у пользователя без заказов `SUM` возвращает `NULL`.
5. **Что делает `ON DELETE CASCADE`?** — удаляет заказы вместе с пользователем.
6. **Где хранится пароль?** — только в `.env` на конкретной машине, не в git.
7. **Что нужно поменять, чтобы подключиться к базе на Aiven?** — только значения в `.env`.
8. **Почему второй запуск не удваивает данные?** — наполнение выполняется при пустых таблицах.
9. **Кто закрывает соединение при исключении?** — `__exit__` контекстного менеджера драйвера,
   то есть `close()` вызывается в любом случае.
10. **Что такое `cursor`?** — объект, через который выполняются запросы и читаются строки.
